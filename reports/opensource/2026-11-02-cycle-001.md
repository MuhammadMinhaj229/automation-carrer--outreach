These are references and selective integration candidates—not systems to merge wholesale. ACIOS should remain a Python + SQLite + CLI + FastMCP application. Do not add another frontend, database, queue service, hosted worker or full job-search product to solve a small provider gap.

**Most important finding:** Before adding features, ACIOS should correct or retire legacy signal paths which can label weak or synthetic records as “Verified Primary.” The newer provenance-led growth scanner should be the only default path for business-event discovery.

## 3. ACIOS correctness risks found

These are code-level observations, not guesses based on old reports.

### P0 — Legacy Prefect signal workflow can create false verification

Inspected:
- [acios/flows/daily_signal_scan.py](https://github.com/MuhammadMinhaj229/automation-carrer--outreach/blob/631f54e741a4863b822b40c62575ccc637c74383/acios/flows/daily_signal_scan.py)
- [acios/providers/signals/rss_provider.py](https://github.com/MuhammadMinhaj229/automation-carrer--outreach/blob/631f54e741a4863b822b40c62575ccc637c74383/acios/providers/signals/rss_provider.py)
- [acios/core/interfaces.py](https://github.com/MuhammadMinhaj229/automation-carrer--outreach/blob/631f54e741a4863b822b40c62575ccc637c74383/acios/core/interfaces.py)
- [tests/test_prefect_flows.py](https://github.com/MuhammadMinhaj229/automation-carrer--outreach/blob/631f54e741a4863b822b40c62575ccc637c74383/tests/test_prefect_flows.py)

Specific issues:

1. `SignalItem.evidence_tier` defaults to `Verified Primary`. That is an unsafe default for a discovery DTO.
2. `RSSSignalProvider` explicitly sets `evidence_tier="Verified Primary (RSS Feed)"`. An RSS aggregator is a discovery source, not automatically a primary source. It also uses the search query itself as `organization_name`, not a verified entity match.
3. The RSS provider turns a missing publication date into the current date. This can make unknown dates appear fresh.
4. `daily_signal_scan.fetch_expansion_signals()` contains a hard-coded list of example organizations and expansion narratives. It uses an ROR organization lookup result's website as the event `source_url`, or the literal fallback `https://verified-news.gcc`. ROR matching can help identify a research organization; it does not verify a funding/plant/contract event.
5. The same workflow assigns today's date, a fixed score of 85, and `evidence_tier="Verified Primary"` to those hard-coded narratives. The text calls them “Verified industrial expansion triggers” without event evidence.
6. `tests/test_prefect_flows.py` asserts at least five results and an Oman/Sohar example. Because the function contains five hard-coded rows, that test can pass without proving that live source discovery or verification works.

**Required remediation:** disable this legacy flow from normal execution or rewrite it to produce discovery-only records with null/unknown event dates when not supplied, real source URLs, real publisher metadata, and no synthetic examples. Change the DTO default to an unverified/discovery state. Add tests proving that failed or empty RSS/registry requests do not manufacture signals. Make event verification a separate source-backed human review.

### P1 — Older Deep Signal Radar fallback fabricates identity details

Inspected [acios/tools/discovery/deep_signal_radar.py](https://github.com/MuhammadMinhaj229/automation-carrer--outreach/blob/631f54e741a4863b822b40c62575ccc637c74383/acios/tools/discovery/deep_signal_radar.py).

When GDELT returns no signals, the fallback builds organization domains from display names, substitutes generic headlines and defaults the country to Oman in some cases. Those values must never be stored as discovered facts or shown as verified company details. Replace this fallback with an explicit `NO_RESULTS` / `PROVIDER_UNAVAILABLE` state, or retrieve existing stored records without changing their factual fields.

### P1 — Keep the newer growth scanner as the business-event path

[acios/tools/discovery/growth_scanner.py](https://github.com/MuhammadMinhaj229/automation-carrer--outreach/blob/631f54e741a4863b822b40c62575ccc637c74383/acios/tools/discovery/growth_scanner.py) explicitly documents that RSS results are leads only and avoids inventing organization domains, event dates, headcounts or contact details. The repository also has a newer source/claim provenance path. Preserve this path and reconcile older signal DTOs/workflows with it before adding new event providers.

### A. freehire — strongest ATS ingestion and lifecycle reference

Repository: [https://github.com/strelov1/freehire](https://github.com/strelov1/freehire)  
Inspected commit: [`ecd109e91939db4a6524d6c73944b634713f408d`](https://github.com/strelov1/freehire/commit/ecd109e91939db4a6524d6c73944b634713f408d)  
License: MIT; actual `LICENSE` inspected.  
Recent activity: commit on 2 November 2026.

Inspected code:
- [internal/ingest/sources/source.go](https://github.com/strelov1/freehire/blob/ecd109e91939db4a6524d6c73944b634713f408d/internal/ingest/sources/source.go)
- [internal/ingest/sources/greenhouse.go](https://github.com/strelov1/freehire/blob/ecd109e91939db4a6524d6c73944b634713f408d/internal/ingest/sources/greenhouse.go)
- [internal/ingest/sources/lever.go](https://github.com/strelov1/freehire/blob/ecd109e91939db4a6524d6c73944b634713f408d/internal/ingest/sources/lever.go)
- [internal/ingest/sources/greenhouse_test.go](https://github.com/strelov1/freehire/blob/ecd109e91939db4a6524d6c73944b634713f408d/internal/ingest/sources/greenhouse_test.go)
- [internal/ingest/pipeline/cooldown.go](https://github.com/strelov1/freehire/blob/ecd109e91939db4a6524d6c73944b634713f408d/internal/ingest/pipeline/cooldown.go)
- [docs/architecture.md](https://github.com/strelov1/freehire/blob/ecd109e91939db4a6524d6c73944b634713f408d/docs/architecture.md)

Useful implementation patterns:

- A narrow `Source` interface and a provider registry isolate ATS-specific API details.
- The Greenhouse list endpoint requests `content=true`; its adapter decodes the response, handles the double-encoded HTML body, normalizes the posting and uses the ATS-native posting ID.
- The Lever adapter selects US/EU endpoints based on board-region configuration, assembles descriptions from the intro, lists and trailing content, and maps structured work-mode, dates and salary only when the source provides interpretable values.
- A board is considered a complete listing only when the response shape is valid. A nil/missing jobs array is treated as an error; an explicit empty array is a legitimate empty board. This prevents malformed responses from being mistaken for zero active jobs.
- The Greenhouse tests cover provider identity, complete-listing marker, request error propagation, entity decoding, script stripping, URL/ID/company/location/date mapping and malformed response cases.
- The documented pipeline uses a stable source/external-ID key, idempotent upserts and per-board health. It distinguishes provider failure from a complete successful crawl.
- `CooldownFor` applies exponential backoff after three consecutive board failures: 6 hours, doubling up to 24 hours. The architecture documentation also describes a separate “quiet board” pause when a complete listing does not change, avoiding needless repeated crawl work.
- The broader architecture uses run-once workers, transactional outboxes and batched search-index drains. These are mature scaling patterns, but ACIOS does not need to adopt PostgreSQL, Meilisearch, Redis or the full worker fleet to use the provider ideas.

**ACIOS decision:** selectively port the design patterns into a small native Python ATS adapter; do not copy the Go application, database, frontend or full job catalogue. Use ATS data only for companies already discovered or deliberately selected by the operator. Hiring activity is a supporting signal, not evidence of an expansion event or a guaranteed vacancy.

## 6. Recommended ACIOS architecture and integration sequence

### Layer 1 — preserve the evidence-first business-signal core

Use the current source/claim/event ledger and existing scanner. Business event providers should return **discovery records**, not verified facts. Primary-source review should remain an explicit action. Preserve separate:
- event date;
- source publication date;
- retrieval timestamp;
- provider/source URL and publisher;
- organization resolution status;
- evidence/verification status;
- heuristic relevance score.

A job posting is not an expansion event. A public job listing can become a separate hiring-intent observation linked to an organization.

### Layer 2 — add a focused ATS adapter, not an ATS aggregator

First supported providers:
1. Greenhouse
2. Lever (with US/EU region configuration)
3. Ashby

Add Workday and SmartRecruiters only after a pilot company set demonstrates demand; they require more detailed pagination and/or detail-fetch handling. Add other ATS platforms only when a target company's official career site is confirmed to use them.

Proposed ACIOS boundary:
- a new typed `JobPosting` / `HiringObservation` contract (do not overload `SignalItem`);
- an `ATSProvider` interface with a capability/region registry;
- small HTTPX-based provider adapters that use the existing timeout, bounded-response and URL/host safety policy;
- a small explicit board registry for companies already selected by a verified business signal or by the operator;
- one normalized job identity: provider + board slug + provider-native posting ID;
- source metadata and last successful complete scan state.

Do not scan hundreds of thousands of companies. Start with the highest-priority organizations in the operator's target list. That keeps the workflow opportunity-led and reduces network, cost and data-quality overhead.

### Layer 3 — model hiring lifecycle conservatively

Recommended state rules:
- A successful complete board response with a posting ID marks it seen.
- One missing run is not enough to close a posting.
- A failed, malformed, partial or timed-out crawl must never advance a missing counter.
- Close only after a configurable number/time window of successful complete misses.
- Reappearance should reopen the same posting identity rather than create a duplicate.
- Use provider-level exponential backoff for repeated failures; keep failure cooldown distinct from “quiet but healthy” boards.

Possible derived hiring-intent observations:
- `new_role`
- `reopened_role`
- `role_cluster_growth`
- `multi_location_role`
- `persistent_open_role`

A hiring-burst/acceleration score must be clearly labelled as a heuristic and shown with its components. Do not treat it as proof that a company has budget, is hiring for a particular unadvertised role, or is likely to hire the ACIOS user.

### Layer 4 — turn signals into workflow hypotheses only after evidence review

For a verified company event plus a verified set of hiring observations, ACIOS may propose an opportunity hypothesis, e.g. “multiple operations/data roles across new locations may indicate reporting or systems coordination complexity.” This remains a hypothesis until independently validated. A prototype suggestion should cite the specific event/roles used and distinguish facts from inference.

### Layer 5 — organization matching

Start with deterministic rules:
- normalize Unicode and company suffixes;
- exact canonical-domain matching;
- registry IDs where available;
- curated aliases;
- preserve conflicting matches and make ambiguous links require review.

Add Splink only after a labelled test set shows deterministic matching is insufficient. Do not automatically merge organizations on fuzzy name similarity alone.

## 8. Cost, privacy, security and policy notes

- Greenhouse, Lever and Ashby public endpoints reduce dependence on generic job-board scraping, but are still subject to provider policies, terms, rate limits and change risk. The endpoint reference recommends caching and low request rates; re-check current vendor documentation when implementing.
- Keep ATS board slugs sourced from the employer's official career URL or another verifiable source. Never guess a board identifier and silently map it to an organization.
- Do not use undocumented LinkedIn/Naukri guest APIs, login scraping, CAPTCHA bypass or browser-session impersonation. Use official/permitted sources and manual review.
- Do not store unnecessary personal information from job descriptions. Focus on job and employer metadata; contact research remains separate, minimized and subject to suppression.
- Keep commercial providers (Firecrawl, Apollo, Clay, etc.) optional and report per-run credit/cost use.
- Splink and OCDS Kit should not become core dependencies before the measured use case justifies their installation/version constraints.
- Preserve ACIOS's existing source provenance, suppression and human approval protections. Do not add autonomous email, application or social-message dispatch.
