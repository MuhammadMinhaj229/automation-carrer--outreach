## 1. Executive decision

ACIOS should not add another crawler framework, ATS aggregator, database, CRM, queue service or scoring platform in this cycle. The current repository already contains a large optional crawler surface, a local SQLite evidence ledger, CLI/MCP entry points, source/claim review records and human approval/suppression controls. The main opportunity is to make those existing capabilities truthful, bounded and business-event-led.

The highest-value finding is not a missing package: **legacy signal paths still manufacture or overstate evidence**. They can turn an RSS result, a registry match, a stale local record or a failed GDELT request into a record labelled “Verified Primary”. That conflicts with the newer provenance-first discovery path and with ACIOS's stated product objective.

The best new research candidates are:

1. **GLEIF LEI API + CC0 registry data** for optional legal-entity identity enrichment of larger businesses. It complements, rather than replaces, ROR and domain/alias matching. No wrapper dependency is needed; a thin HTTPX adapter can be built later.
2. **Trafilatura** as an optional extraction-only library if a labelled benchmark proves that the current BeautifulSoup extractor misses article body/date metadata. Feed it HTML already fetched by ACIOS; do not delegate network access to its downloader.
3. **Dateparser** for explicitly stated human-readable dates only, anchored to the article publication date. It must never turn a retrieval timestamp or an unknown date into an event date.
4. **Open Contracting Data Standard / OCDS Kit** for a jurisdiction-specific procurement adapter once an actual target portal and its data licence are selected.
5. **freehire** as a high-quality reference for complete-listing proofs, idempotent lifecycle handling, quiet-board backoff and bounded ATS ingestion. ATS remains a supporting hiring-intent signal, not the core product.

No candidate passed the combined usefulness, non-duplication, runtime compatibility and test-validation gates for a production code integration today. This is an explicit no-code-change decision, not a claim that the repository is complete.

### Existing strengths to preserve

- Local SQLite is the canonical store; provider SDKs remain adapters.
- Source documents, discovery events, claims, source reviews and claim reviews already provide a useful evidence foundation.
- A claim cannot become VERIFIED_PRIMARY without an official-primary source classification and a human review. CORROBORATED currently requires two named publishers.
- Newer discovery tests assert that a generic headline does not become a company, an aggregator result does not invent a website or event date, and a user-supplied target is not itself a verified trigger.
- The native HTTP crawler manually follows at most three redirects, validates each destination before fetching it, re-checks robots after redirects, rejects non-HTML content and caps the body at 2 MB.
- Suppression, content-hash-bound draft approvals and human-controlled dispatch remain outside the scope of this research. No outreach was sent.

## 5. ACIOS correctness and security findings

### P0 — Legacy Prefect workflow manufactures verified business signals

Inspected:
- daily_signal_scan.py: fetch_expansion_signals and filter_and_persist_signals
- rss_provider.py: fetch_signals and _score_headline
- interfaces.py: SignalItem and SignalProvider
- database.py: legacy signals evidence_tier default
- mcp_server.py: run_prefect_workflow
- tests/test_prefect_flows.py

The flow contains five hard-coded organization/event narratives. For each, it performs an ROR name lookup, then uses the first ROR website as the event source URL or a synthetic https://verified-news.gcc URL. It assigns the current date, score 85 and “Verified Primary”. ROR can help resolve an organization; it does not verify a facility, funding, contract or pilot event. The flow then writes directly to the legacy signals table rather than the newer source/claim provenance path.

The RSS provider separately labels Google News RSS as “Verified Primary (RSS Feed)”, uses the query string as organization_name and substitutes the current date when publication time is missing. SignalItem and the legacy signals table also default to “Verified Primary”.

**Required fix before expanding features:** change the legacy DTO/database default to an explicit discovery/unverified state; remove hard-coded rows and synthetic source URLs; make missing dates null; distinguish publisher article URL from aggregator URL; route all event observations through the newer source/event ledger; keep claim verification human-reviewed. Add regression tests for empty, malformed, timed-out and unresolved provider results.

### P0 — GDELT path misstates identity, date, country and evidence

Inspected deep_signal_radar.py: scan_gdelt_news_graph.

- It derives organization_name from the first label of the article domain. A publisher domain is not the company named in a headline.
- It treats GDELT seendate as published_date. A GDELT indexing/seen timestamp is not necessarily the article's publication date and is certainly not the business event date.
- It truncates the supplied country string to two characters for sourcecountry. Official GDELT examples accept a full country token (for example unitedarabemirates) or a FIPS code; taking the first two characters of a human-readable country name is not a safe mapping.
- Global/no-country searches default target_country to Oman.
- It labels the result “Verified Primary News” and invents generic talent_demand.
- If GDELT returns nothing or fails, it converts old local signals into new records, fabricates a .com domain when missing, generates a generic headline and defaults the date to today.

**Required fix:** preserve GDELT output as aggregator discovery metadata only; store seen/index time separately; never infer the subject organization from publisher domain; use an explicit ISO/FIPS country mapping; remove the fabricated fallback and return NO_RESULTS or PROVIDER_UNAVAILABLE. A failed provider must not create a lead.

### P1 — RSS retrieval is not bounded by the shared crawler policy

The new growth scanner calls feedparser.parse(feed_url), which lets feedparser perform its own network request. The URL is a fixed Google News endpoint, so this is not an arbitrary user-controlled SSRF vector, but it bypasses ACIOS's shared HTTPX timeout, response-byte cap, retry/rate budget and failure-state model.

**Recommendation:** fetch the fixed feed through a bounded HTTPX client (timeout, max response bytes, one request per host budget, Retry-After-aware 429 handling), then pass response bytes to feedparser.parse. Preserve feed source and publisher article URL separately.

### P1 — Default crawler order conflicts with the local-first architecture

catalog.py returns crawl4ai, crawlee, scrapling, scrapy, firecrawl, then httpx when Firecrawl is not explicitly preferred. If an optional browser/framework adapter is installed, it can be selected before the built-in HTTP path. If FIRECRAWL_API_KEY is set, the remote paid provider can be tried before HTTPX even when ACIOS_CRAWLER_PREFER_FIRECRAWL is false.

This conflicts with docs/LOCAL_FIRST_ARCHITECTURE.md, which specifies bounded HTTP first and browser rendering only for JavaScript gaps. Reorder to native HTTP first; make remote Firecrawl an explicit opt-in, not a silent fallback. Keep browser frameworks explicit or use them only after a native extraction failure that is classified as a rendering gap.

### P1 — Egress guard is an operational assertion, not a technical proof

The production crawler gate checks ACIOS_CRAWLER_LOCAL_EGRESS_GUARD=true. That variable is a self-attestation; it does not inspect firewall or network policy. Native HTTP validates DNS before each request and manually validates redirect destinations, but DNS can change between validation and connection. Other optional adapters may follow redirects internally and validate the final URL only after the fetch.

Keep the current fail-closed production default. Before enabling local browser/crawler adapters in production, enforce outbound private/loopback/link-local/metadata blocking at the network boundary, verify redirect behavior for each adapter, and test DNS rebinding. Also cap robots.txt response size; the current robots request has a timeout but reads response.text without an explicit byte cap.

### P1 — Canonical URL and evidence hash semantics are incomplete

record_source_document lowercases scheme/host and removes fragments, but source_documents uniqueness is (url, content_hash). canonical_url is stored but is not the uniqueness key or normalized by the repository. Tracking parameters, URL aliases and equivalent trailing-slash forms can remain separate records.

The RSS discovery path stores an identifier derived from URL/headline/excerpt in the field named content_hash even though it has not fetched the publisher page body. Keep a discovery fingerprint distinct from a fetched-source body hash. Do not call a metadata fingerprint a content hash.

### P1 — Test suite contains unmarked live-provider tests

pyproject.toml configures pytest to exclude tests marked live_integration. tests/test_prefect_flows.py is not marked, calls live Google News/ROR providers and asserts the presence of Oman/Sohar example rows. It can fail because of network/provider changes or pass because hard-coded rows exist; it does not prove the discovery contract.

Move live tests behind the live_integration marker and make the default suite use fixtures/mocks. Remove assertions that require seeded example organizations. Add a provider contract test that proves failure/empty responses create zero records.

### P2 — Runtime support and security audit coverage do not match declared support

- pyproject declares Python >=3.10, but CI tests only 3.11 and 3.12.
- pip-audit scans requirements.txt, while many optional dependencies are declared in pyproject extras.
- Bandit scans acios/core and acios/models, not crawling/providers where network handling lives.
- The repository's AGENTS.md says code changes should use a feature/refactor branch, while the user-requested operating mode is direct main. No branch protection was bypassed. Resolve this developer-policy conflict explicitly before future automated source-code commits; never bypass required checks.

### P2 — MongoDB compatibility code contradicts the current product boundary

docs/LOCAL_FIRST_ARCHITECTURE.md says MongoDB/hosted workers are retired compatibility paths. Some repository docstrings and backend selection logic still describe MongoDB as a production backend, while source/claim provenance is SQLite-only and raises if the Mongo backend is active. Keep SQLite as the default and either remove the obsolete path in a separately tested migration or clearly isolate it so an environment variable cannot silently disable provenance-led discovery.

## 7. Public source and standards shortlist

These are data services or standards, not open-source software dependencies. Their data rights, endpoint availability and API policy must be checked separately from any client code.

### GLEIF LEI API — best additional legal-entity identity source

Official sources: https://www.gleif.org/en/lei-data/gleif-api and https://www.gleif.org/en/about-lei/gleif-concatenated-files/gleif-golden-copy

- GLEIF describes its LEI reference data as freely accessible; ROR-style broad research IDs are not a substitute for LEIs.
- Official ROR/GLEIF sources distinguish the legal entity registry from the research-organization scope.
- GLEIF supports legal-entity name search, filters, related identifiers and ownership relationships. The official API is free and does not require an API key in the published documentation.
- The registry data is CC0; the website's general content has a separate licence. Use the data licence, not the website content licence.
- A public rate limit was not found in the official material checked. Use a conservative local request budget, bounded pages, caching and Retry-After handling until GLEIF documents a limit.
- Coverage is limited to entities with LEIs; absence is not proof that a company is not real.
- Recommendation: future thin HTTPX adapter; store LEI, legal name, jurisdiction, registration status, legal form, parent links, retrieval time and raw source URL. Do not merge automatically on name alone.

### ROR — retain for research organizations only

Official sources: https://ror.org/ and https://ror.org/about/terms/

- ROR registry records are CC0 and cover research/funding organizations; they are not a comprehensive corporate registry.
- ROR API v2 is the current schema/API. ROR says new client-ID registration is temporarily paused and no rate limits are currently enforced based on client-ID status while the pause remains.
- Current ACIOS RORClient uses a 10-second urllib timeout but lacks a shared response-byte cap, persistent cache and rate budget.
- Recommendation: keep ROR as an optional research-institution resolver; never use an ROR website match as proof of a business event.

### GDELT DOC 2.0 — discovery index, not verification

Official documentation: https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/

- The DOC API supports ArticleList mode, JSON/RSS outputs, explicit date windows and a MAXRECORDS cap up to 250. Its default time window is the last three months.
- It is a hosted API/data service, not an open-source package. No API key is shown in the official DOC API examples; an official rate limit or service-level guarantee was not found in the documentation checked.
- Article title/URL/seen-time metadata can be used to discover candidate coverage. The original article text remains subject to the publisher's rights and site terms.
- Recommendation: use as a low-priority aggregator source only; never call its result primary evidence and never substitute seendate for publication/event date.

### SEC EDGAR — strong U.S. filing source

Official sources: https://www.sec.gov/about/developer-resources and https://www.sec.gov/about/webmaster-frequently-asked-questions

- Company submissions and extracted XBRL data are available through REST APIs on data.sec.gov; company and latest-filing searches also provide RSS.
- SEC's current published fair-access guidance is no more than 10 requests per second per user across machines. It requires a declared descriptive User-Agent for programmatic downloads and warns against unclassified automated crawlers.
- SEC FAQ says government-created SEC content and EDGAR public filing content are free to access and reuse, subject to stated exceptions such as third-party stock art.
- Recommendation: a future bounded U.S.-only filing adapter for relevant public companies; use accession number/CIK identity and filing acceptance time, preserve form type, and do not generalize SEC coverage to private or non-U.S. companies.

### Open Contracting Data Standard — procurement normalization

Official sources: https://standard.open-contracting.org/latest/en/schema/ and https://www.open-contracting.org/data-standard/

- OCDS 1.1.5 uses JSON Schema release, release-package and record-package structures.
- OCDS standardizes public contracting data; it is not an e-procurement application or a guarantee that a portal exposes an API.
- UK Find a Tender publishes OCDS release/record package APIs and documents filters by publication date, stage, notice and procurement process: https://www.find-tender.service.gov.uk/apidocumentation/1.0/GET-ocdsRecordPackages
- Recommendation: select a jurisdiction and portal first; inspect each publisher's licence, pagination, update semantics and terms. Add a thin source adapter, then optionally use OCDS Kit if Python >=3.11 is adopted.

### Schema.org NewsArticle — useful metadata vocabulary

Official sources: https://schema.org/NewsArticle and https://schema.org/datePublished

- Extract datePublished, dateModified, publisher, author, headline, articleBody and canonical URL when present.
- datePublished is a publication/broadcast date, not the business event date. Store these fields separately.
- JSON-LD is untrusted source input; validate shape and URL, and do not trust arbitrary script content as a verified claim.

### Recommended event scoring design

Do not combine every factor into a single opaque “growth score”. Keep separate, inspectable components:

1. **Evidence quality:** official primary, independent secondary, aggregator, unknown.
2. **Event type:** funding, facility, plant, contract, tender, pilot, partnership, sustainability programme, operational transformation.
3. **Event novelty:** new, update, repeated coverage, duplicate.
4. **Date quality:** event date, publication date, retrieval date, unknown; never substitute one for another.
5. **Recency:** decay only when a real publication/event date exists.
6. **Source diversity:** distinct publisher domains and primary-source corroboration, not repeated URLs from one syndicator.
7. **Organization fit:** sector/geography/project alignment, separate from evidence confidence.
8. **Hiring-intent support:** separate ATS observations linked to the organization; never treat a vacancy as proof of an expansion event.

For trend detection, begin with daily organization + event-category counts, minimum-volume thresholds, rolling 7/30/90-day windows and a robust trailing median/MAD or smoothed Poisson baseline. Record the numerator, baseline, window and threshold. Do not add PELT until there is enough history to validate change points. No score should be presented as a probability of reply, referral, interview or hiring without labelled outcomes and calibration.

### Recommended organization matching sequence

1. Normalize Unicode, punctuation, legal suffixes and whitespace while retaining the raw name.
2. Match stable identifiers first: LEI, ROR (research orgs), official registration IDs where legally available.
3. Match canonical official domain and known domains/aliases.
4. Use name + country/jurisdiction + location as a review candidate.
5. Use RapidFuzz only to rank possible aliases, never to merge automatically.
6. Add Splink only after a labelled benchmark demonstrates that deterministic matching is inadequate.
7. Preserve parent, subsidiary, brand and facility relationships as separate entities or explicit links; do not collapse them into one company record.
